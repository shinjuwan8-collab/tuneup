# content-draft

Effort: routine for docs/README, hard for persuasive or public-facing pieces.

## Steps

1. **Brief**: state audience, the one thing they should take away, desired
   action after reading, and tone (match any examples the user provided —
   examples beat descriptions of tone).
2. **Outline**: headline + section list with a one-line point per section.
   The piece should be skimmable from headers alone.
3. **Draft**: write it. Rules:
   - Lead with the payoff, not the setup.
   - One idea per paragraph; concrete examples over adjectives.
   - Numbers and names must come from provided material or verified research —
     never invented.
4. **Self-edit pass** (do this as a separate pass, not while drafting):
   - Cut 15–20% of words. Kill throat-clearing openers and hedges.
   - Read the first sentence of every paragraph in sequence — that skeleton
     must tell the whole story.
   - Check every factual claim against source material; flag anything
     unverifiable in a note to the user rather than shipping it silently.
5. **Deliver**: the piece, then a 3-line note: intended audience, claims that
   need the user's verification, and one suggested variant (shorter/longer/
   different angle) if useful.

## Constraints

- Match the language of the audience (this project's users are Japanese —
  ask or infer which language the piece needs; don't default to English).
- Never fabricate quotes, stats, or testimonials.
- For docs: every command shown must have been actually run, with output checked.
