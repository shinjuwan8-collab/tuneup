# Repo & workflow-asset audit — 2026-07-02

**TLDR**: The repo contained **no workflow assets** (no CLAUDE.md, skills,
prompt library, or memory notes) — so instead of auditing stale assets, this
audit founded the system (see CLAUDE.md, `.claude/skills/`, `notes/`,
`prompts/`). The app code itself has 7 findings: 1 breaks-now, 2 will-break,
1 costs-money, 3 confusing. The most important: **two parallel half-finished
stacks live in the tree, and one of them cannot build.**

## Findings

### 1. Dead FastAPI stack; `frontend/` cannot build (breaks-now)
- `frontend/src/main.jsx:3` imports `./App.jsx` — **the file does not exist**.
  `frontend/` has `index.html`, `package.json`, `vite.config.js`, `main.jsx`
  but no App component, so `vite build` there fails.
- `main.py` (FastAPI) serves `POST /api/claude` (`main.py:14`) and static files
  from `frontend/dist` (`main.py:11`), but the only frontend that exists
  (root `src/App.jsx:15`) calls `POST /api/chat`, which only `server.js:11`
  serves. The FastAPI variant can never work with the real frontend.
- Proxy targets also disagree: root `vite.config.js:8` → `:3000` (Express);
  `frontend/vite.config.js:9` → `:8000` (FastAPI).
- **Fix**: delete `main.py`, `requirements.txt`, `frontend/` (pending owner
  decision — recorded in `notes/workflow.md`).

### 2. Root `dist/` not gitignored (will-break)
- `.gitignore:7` ignores `frontend/dist/`, but the canonical build
  (`npm run build`, root `vite.config.js`) outputs to root `dist/`, which
  `server.js:34` serves. First build + `git add .` commits build artifacts.
- **Fix**: add `dist/` to `.gitignore`.

### 3. README doc drift (will-break)
- `README.md:33` says model `claude-sonnet-4`; code uses `claude-sonnet-4-5`
  (`src/App.jsx:18`). Whoever follows the README reasons about the wrong model.
- `README.md:26` build command `npm install && npm run build` is correct for
  the Node stack, but the README never warns that `main.py`/`frontend/` are
  dead — a new contributor can easily start extending the wrong stack.
- **Fix**: correct the model name; add one line marking the canonical stack
  (now also covered by CLAUDE.md).

### 4. Open proxy on `/api/chat` (costs-money)
- `server.js:24` forwards `req.body` verbatim to the Anthropic API. Any
  visitor to the deployed site can choose any model and any `max_tokens` on
  your API key; there is no rate limit.
- **Fix**: server-side allowlist — pin `model` and cap `max_tokens` on the
  server; accept only `messages`/`system` from the client. Consider basic
  rate limiting.

### 5. Prompts inline in UI code (confusing)
- Three Claude prompts live inside `src/App.jsx` (lines ~245, ~302, ~333),
  entangled with React state logic. Hard to version, test, or reuse.
- **Fix (when next touched)**: extract to `src/prompts.js`; keep `parseJSON`'s
  tolerance for fenced JSON.

### 6. React pinned in `devDependencies` at two versions (confusing)
- Root `package.json:16` pins react `^18.2.0` (as devDependency);
  `frontend/package.json:12` pins `^18.3.1`. Works because Vite bundles, but
  two manifests disagree about the same app. Resolved by deleting `frontend/`.

### 7. Duplicate `index.html`/`main.jsx` pairs (confusing)
- Root and `frontend/` each carry near-identical `index.html` and `main.jsx`
  (differing titles at `index.html:6` vs `frontend/index.html:6`). Same root
  cause as finding 1.

## Not findings (checked, fine)

- No secrets in tree: `.env` is gitignored (`.gitignore:3`); `.env.example`
  holds a placeholder only.
- `server.js` error handling returns upstream status codes correctly.
- `src/App.jsx` clamps model-returned scores to 1–5 (`App.jsx:356–358`) —
  good output-distrust hygiene.
- Root build path is self-consistent: `vite build` → `dist/` → served by
  `server.js:34`.
